28.1 Confidence Calibration: Field-Level Confidence Scoring

↑ top

Definition

A confidence score is the model's self-reported probability that an extracted field value is correct (e.g. "invoice total = $4,210.00", confidence 0.93). Calibration is the agreement between that stated confidence and the observed accuracy. A model is well-calibrated when, among all predictions it labels 0.90, roughly 90% actually turn out correct.

Field-level means the score is attached to each extracted field independently (invoice number, date, total…), not to the whole document, because a document can be 99% right on the date and 40% right on a handwritten total.

Key Formulas / Metrics

# Aggregate token probabilities into one field score (common choices) conf_field = min(p_token1, …, p_tokenK) # conservative (weakest link) conf_field = (∏ p_tokenᵢ)^(1/K) # geometric mean of token probs
# Expected Calibration Error — bins predictions, compares conf vs accuracy ECE = Σ_{m=1..M} (|B_m| / N) · | acc(B_m) − conf(B_m) | # B_m = predictions in confidence bin m ; N = total predictions
# Brier score — mean squared error of probabilistic predictions (lower = better) Brier = (1/N) · Σ (fᵢ − oᵢ)² # fᵢ = predicted prob, oᵢ ∈ {0,1} outcome
# Temperature scaling — post-hoc recalibration; tune T on a validation set calibrated_prob = softmax( logits / T ) # T>1 softens overconfidence

Worked Example (illustrative)

Take 100 field extractions the model labelled with confidence ≈ 0.90. Suppose 82 were actually correct. Then for that bin conf = 0.90, acc = 0.82, gap = 0.08. If a second bin (conf ≈ 0.70, 200 items) shows accuracy 0.71, gap = 0.01. With only these two bins over N = 300:

ECE = (100/300)·|0.82−0.90| + (200/300)·|0.71−0.70| = 0.333·0.08 + 0.667·0.01 ≈ 0.033 # ~3.3% average miscalibration

Reading: the model is slightly overconfident in its high band (says 90, delivers 82) but well-behaved at 70. Fix: temperature scaling or a tighter auto-approve threshold for the 0.90 band (see 28.4).

Visualization — Reliability diagram

A reliability diagram plots mean predicted confidence (x) against observed accuracy (y). Perfect calibration is the diagonal; bars below the diagonal = overconfident.

⚠️ Common Pitfalls
  • Treating a raw softmax / log-prob as if it were a calibrated probability. Neural models are typically overconfident out of the box.
  • Calibrating at the document level and reusing that number for every field — fields differ wildly in difficulty.
  • Reporting only average confidence and calling it "accuracy". Confidence ≠ accuracy until you measure calibration.
  • Calibrating on the training set (leaks) instead of a held-out validation set.
💡 Tips & Tricks
  • Mnemonic "C≠A until you draw the diagram" — Confidence isn't Accuracy until a reliability diagram / ECE proves it.
  • ECE in one line: weight each bin's |confidence − accuracy| by how many items are in it.
  • If bars sit below the diagonal → overconfident → raise T or thresholds. Above → underconfident.
🎯 Exam Strategy Expect a small table of bins (count, mean confidence, accuracy) and a "compute the ECE" ask. Weight by bin size — the classic trap is a plain average of the gaps. Also watch wording: "the model reports 0.95" is a confidence claim, not an accuracy claim; answers that equate the two are distractors.

28.2 Stratified Sampling for Error Rate Measurement

↑ top

Definition

To learn the true error rate of an extraction system you can't hand-check everything, so you audit a sample. Stratified sampling splits the population into homogeneous groups (strata — e.g. by document type) and samples within each. Compared to simple random sampling it gives a lower-variance estimate and guarantees rare-but-important strata are actually represented.

Key Formulas / Metrics

# Sample size for a proportion (error rate p), margin of error E, confidence z n₀ = z² · p·(1−p) / E² n = n₀ / (1 + (n₀−1)/N) # finite population correction (FPC) # z=1.96 for 95%. Use p=0.5 when unknown (worst-case, max variance).
# Stratified error-rate estimate = weighted sum of per-stratum rates p̂_strat = Σ_h W_h · p̂_h # W_h = N_h / N (stratum's share of population) Var(p̂_strat) = Σ_h W_h² · p̂_h(1−p̂_h) / n_h
# Allocating the total sample n across strata Proportional: n_h = n · W_h Neyman (optimal): n_h = n · (N_h·S_h) / Σ(N_k·S_k) # more sample where variance S_h is high

Worked Example (illustrative)

Population N = 50,000 extracted fields across 3 doc types. Target margin E = 0.03 at 95% confidence, unknown p ⇒ use p = 0.5:

n₀ = 1.96² · 0.5·0.5 / 0.03² = 3.8416·0.25/0.0009 ≈ 1067 n = 1067 / (1 + 1066/50000) ≈ 1045 # FPC barely changes it — population is large

Now allocate proportionally and compute the stratified rate (example measured values):

Stratum (doc type)NhWhnh (prop.)errors foundp̂hWh·p̂h
Invoices30,0000.60627190.0300.0180
Receipts15,0000.30314220.0700.0210

Stratified error rate p̂_strat ≈ 5.1%. Note the trap: naively averaging the three raw rates (3.0 + 7.0 + 11.5)/3 = 7.2% overstates error, because contracts (worst) are only 10% of volume. Weighting by Wh is what makes it correct.

⚠️ Common Pitfalls
  • Averaging raw per-stratum rates instead of weighting by stratum size.
  • Thinking sample size scales with population — it scales with variance and the desired margin E. A 50k and a 5M population need almost the same n.
  • Strata so small that n_h is a handful — per-stratum estimates become noise.
  • Sampling only what the router auto-approved (survivorship): you must also audit the auto-approved stream, or you never see its silent errors.
💡 Tips & Tricks
  • Rule of thumb "Sample size scales with variance, not population size."
  • Unknown error rate? Use p = 0.5 — it maximises p(1−p) and gives the safest (largest) n.
  • Neyman = "spend sample where it's noisy": bigger and more variable strata get more samples.
  • Halving the margin E roughly quadruples the required n (E is squared).
🎯 Exam Strategy If a question gives per-stratum error rates and stratum sizes and asks for the overall / stratified error rate, compute Σ W_h·p̂_h — never the plain mean. If it gives E and confidence and asks for n, plug into z²p(1−p)/E² and only apply FPC when the population is small relative to n. Distractors often swap proportional and Neyman allocation, or forget to square E.

28.3 Accuracy Segmentation by Document Type and Field

↑ top

Definition

Segmentation means reporting accuracy metrics sliced by meaningful dimensions — here the (document type × field) matrix — instead of one headline number. A 96% aggregate accuracy can hide a field that is 55% accurate. Segmentation localises where the pipeline actually fails so remediation (28.5) is targeted.

Key Formulas / Metrics

# Per-segment classification metrics (computed within each cell) Precision = TP / (TP + FP) Recall = TP / (TP + FN) F1 = 2·P·R / (P + R) # Field-value extraction metrics Exact-Match(EM) = #exactly-correct-values / #values CER = edit_distance(pred, gold) / len(gold) # Character Error Rate

Worked Example — accuracy heatmap (illustrative)

Exact-match accuracy per (doc type × field). Green = strong, red = weak. Instantly you see handwritten totals on receipts and signature dates on contracts are the failure hotspots — the aggregate 91% hid them.

Simpson's paradox watch: a field can look fine in aggregate yet be poor in the segment that carries most business risk. Always keep the support (count) beside each cell — a 0.58 over 12 samples is a hypothesis, over 600 it's a finding.

⚠️ Common Pitfalls
  • Reporting a single aggregate accuracy that averages away a critical weak segment.
  • Comparing segments with wildly different support as if equally reliable.
  • Using plain accuracy on imbalanced fields where a field is usually blank — precision/recall or F1 is more honest.
  • Over-segmenting until every cell has 3 samples — noise masquerading as signal.
💡 Tips & Tricks
  • Mnemonic "Segment until it stops surprising you" — stop slicing when new cuts no longer reveal new weak spots.
  • Always print support next to each metric; a low score on tiny support is a to-do, not a verdict.
  • Sort the heatmap by weakest cell — the top-left of your attention should be the worst (type × field).
🎯 Exam Strategy Segmentation questions usually hand you a matrix or confusion table and ask "which segment needs review / retraining first?" Pick the one that is both low accuracy AND high volume/risk — not merely the single lowest number on tiny support. Watch distractors that point at a red cell backed by only a handful of samples.

28.4 Routing Decisions Based on Calibrated Confidence

↑ top

Definition

Routing uses the calibrated confidence (from 28.1) plus business cost to decide each field's fate: auto-approve, spot-check, full human review, or escalate/reject. The threshold isn't arbitrary — it's chosen to balance the cost of an undetected error against the cost of human review.

Key Formulas / Metrics

# Expected cost of AUTO-APPROVING a field at calibrated confidence c E[cost_auto] = (1 − c) · C_error # prob wrong × cost of a slipped error E[cost_review] = C_review # fixed cost of a human check # Auto-approve is rational only when it's cheaper: Auto-approve if (1 − c)·C_error ≤ C_review ⇔ c ≥ 1 − (C_review / C_error) # the break-even threshold τ*

So the "right" threshold falls out of costs: if a slipped error costs 100× a review, τ* = 1 − 1/100 = 0.99. If it costs only 5×, τ* = 0.80. High-stakes fields get high thresholds.

Worked Example — routing table (illustrative thresholds)

Calibrated confidenceActionRationale
≥ 95%Auto-approveHigh reliability, low error risk (example value)
80–94%Light-touch spot checkModerate risk — sample a fraction for QA
50–79%Route to human reviewerUncertain — needs verification
< 50%Escalate / rejectHigh error risk — do not auto-use

These bands are illustrative. In practice each field's thresholds come from its own cost ratio and its own calibration curve. A "signature date on a contract" (28.3 showed 0.62 accuracy) should get a much higher review threshold than an "invoice number".

Visualization — routing flow

⚠️ Common Pitfalls
  • Routing on raw uncalibrated scores — the whole table is meaningless if 0.95 ≠ 95% accurate.
  • One global threshold for all fields, ignoring that error costs differ by field and doc type.
  • Ignoring cost asymmetry — a slipped payment error ≫ a review minute; symmetric thresholds under-protect high-stakes fields.
  • Never auditing the auto-approved stream, so threshold drift goes unnoticed.
💡 Tips & Tricks
  • Mnemonic "Route on calibrated confidence, cost sets the cut."
  • Break-even threshold shortcut: τ* = 1 − C_review / C_error. Expensive errors → threshold near 1.
  • Higher threshold ⇒ fewer auto-approvals ⇒ more human cost but fewer slipped errors. It's a dial, not a truth.
🎯 Exam Strategy "Best next action" questions give a field's confidence + a cost scenario. Compute (or reason about) (1−c)·C_error vs C_review and pick the action that minimises expected cost — not the one that "feels safe". If the stem stresses that errors are catastrophic, the correct answer routes to human even at fairly high confidence. Distractors typically auto-approve a high-stakes low-confidence field, or apply one threshold to everything.

28.5 Hands-On: Designing a Human-in-the-Loop Review Pipeline

↑ top

Definition

The capstone: assemble 28.1–28.4 into one operating pipeline where machine extraction and human reviewers collaborate, and where measured error feeds back to improve the system. HITL = the model handles volume, humans handle uncertainty, and the boundary between them is set by calibrated confidence and cost.

Pipeline stages

  1. Ingestion — receive & classify documents by type (drives segmentation, 28.3).
  2. Field extraction — model extracts each field value + raw scores.
  3. Confidence scoring & calibration — convert raw scores to calibrated per-field confidence (28.1).
  4. Routing — apply per-field, cost-aware thresholds (28.4).
  5. Sampling / QA — stratified audit of the auto-approved stream to measure true error (28.2).
  6. Human review — reviewers correct routed / escalated items; corrections are logged as ground truth.
  7. Feedback loop — audit + corrections update the accuracy segmentation (28.3), recalibrate confidence (28.1), and re-tune thresholds (28.4).

Worked Example — a design decision (illustrative)

Contracts show 0.62 accuracy on "date" and slipped-date errors are costly (C_error ≈ 60× C_review). Break-even τ* = 1 − 1/60 ≈ 0.983. Because calibrated confidence on that field rarely exceeds 0.90, in practice every contract date is routed to a human — correct outcome. Meanwhile invoice numbers (0.99 accuracy, cheap errors) auto-approve at ≥ 0.95, keeping human cost focused where it pays off.

⚠️ Common Pitfalls
  • No feedback loop — a "HITL pipeline" that never feeds corrections back is just review theatre; calibration drifts.
  • Not monitoring for data drift — new document formats silently degrade a field the router still trusts.
  • Auditing only routed items and never the auto-approved stream (see 28.2 survivorship).
  • Reviewer fatigue / no inter-annotator agreement check — the "ground truth" itself becomes noisy.
💡 Tips & Tricks
  • Mnemonic for the loop: "Extract → Calibrate → Route → Sample → Segment → Repeat" (ECRSSR — "each careful reviewer surfaces slipped risk").
  • A HITL pipeline without a feedback edge is an open loop — closing it is what makes it "learning".
  • Design thresholds per (field × type), not globally — 28.3's heatmap tells you where.
🎯 Exam Strategy System-design questions describe a pipeline missing one piece and ask what to add. The answer is almost always the measurement or feedback component (stratified audit, recalibration, drift monitoring) — the parts teams forget. If a design "auto-approves everything above a fixed global threshold with no auditing", the correct fix adds sampling + feedback, not a bigger model.

Chapter Summary Cheat Sheet

28.1 Calibration

  • Confidence = self-reported P(correct); calibrated ⇒ conf ≈ accuracy.
  • ECE = Σ (|B_m|/N)·|acc−conf| — weight by bin size.
  • Brier = (1/N)Σ(f−o)²; temperature scaling softmax(logits/T).
  • Below diagonal = overconfident.

28.2 Stratified sampling

  • n₀ = z²p(1−p)/E²; FPC n = n₀/(1+(n₀−1)/N).
  • p̂_strat = Σ W_h·p̂_h — never plain-average rates.
  • Unknown p → use 0.5. Neyman: sample where variance is high.
  • Size tracks variance, not population.

28.3 Segmentation

  • Slice accuracy by (doc type × field); aggregate hides weak cells.
  • P, R, F1, Exact-Match, CER per segment; keep support beside metric.
  • Fix worst high-volume/high-risk cell first (Simpson's paradox).

28.4 Routing

  • Route on calibrated confidence + cost.
  • Break-even τ* = 1 − C_review/C_error.
  • Auto-approve if (1−c)·C_error ≤ C_review.
  • Per-field thresholds; costly errors → τ near 1.

28.5 HITL pipeline

  • Ingest → Extract → Calibrate → Route → Sample/QA → Human → Feedback.
  • No feedback loop = not learning; monitor drift.
  • Audit the auto-approved stream, not just routed items.

Exam quick-fires

  • Weight, don't average (strata & bins).
  • Square E in sample size.
  • "Best action" = minimise expected cost.
  • Missing component ≈ measurement/feedback.

Self-Check Quiz

↑ top

Try each before opening the answer. (All numbers illustrative.)

Q1. A model labels 200 fields with confidence ≈ 0.95, and 168 are correct. What does this tell you, and in which direction is it miscalibrated?
Observed accuracy = 168/200 = 0.84 vs stated 0.95 → gap 0.11. The model is overconfident in this band (bars below the diagonal). Fix: temperature scaling (T>1) and/or raise the auto-approve threshold for this field.
Q2. Strata error rates: A (N=8,000) 2%, B (N=1,500) 9%, C (N=500) 15%. What is the overall stratified error rate — and what's the trap answer?
Weights: A=0.80, B=0.15, C=0.05. p̂ = 0.80·0.02 + 0.15·0.09 + 0.05·0.15 = 0.016 + 0.0135 + 0.0075 = 0.037 ≈ 3.7%. Trap answer = plain average (2+9+15)/3 = 8.7%, which massively overstates error because C is only 5% of volume.
Q3. You need a 95% CI with margin E = 0.02 and have no prior estimate of the error rate. Roughly what sample size (ignore FPC)?
Use p = 0.5 (worst case). n₀ = 1.96²·0.25/0.02² = 3.8416·0.25/0.0004 ≈ 2,401. (Halving E from 0.04 to 0.02 quadruples n — E is squared.)
Q4. A field has calibrated confidence 0.90. A slipped error costs $50; a human review costs $2. Auto-approve or review?
E[cost_auto] = (1−0.90)·$50 = $5. E[cost_review] = $2. Since $5 > $2, route to review. Break-even τ* = 1 − 2/50 = 0.96, so 0.90 is below threshold.
Q5. Your aggregate extraction accuracy is 94%, but finance keeps hitting wrong contract totals. What analysis do you run and what's the likely finding?
Run accuracy segmentation by (doc type × field). Likely finding: contract "total/amount" (or "date") is a low-accuracy cell hidden by the high-volume, high-accuracy invoice fields — aggregate masking / Simpson's paradox. Remediate that segment (higher review threshold, recalibration).
Q6. A pipeline auto-approves every field above a single fixed 0.9 threshold and never samples the output. Name two defects and the fix.
Defects: (1) single global threshold ignores per-field cost/accuracy; (2) no auditing/feedback of the auto-approved stream → silent drift and no recalibration. Fix: per-(field×type) cost-aware thresholds + stratified sampling of auto-approved items feeding a recalibration/threshold-tuning loop.
Q7. Why is p = 0.5 used for sample-size planning when the true error rate is unknown?
Because p(1−p) is maximised at p = 0.5, giving the largest (most conservative) required sample size — so you're guaranteed enough samples regardless of the true rate.
Q8. You have a fixed review budget. Allocation across strata: proportional or Neyman — and why?
Neyman allocation is optimal for minimising the variance of the overall estimate: n_h ∝ N_h·S_h, spending more sample on strata that are both large and high-variance. Proportional (n_h ∝ N_h) is simpler but ignores variance — fine when strata variances are similar.
